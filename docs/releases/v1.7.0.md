# ken v1.7.0 — ken-mcp mmaps the embedding model

A steady-state-memory release, prompted by `ken-mcp` being observed resident at ~1.6 GB. **The 1.0 public API and default retrieval behavior are unchanged — upgrading is safe with no config changes.**

## Highlights

**`ken-mcp` now mmaps the embedding model instead of heap-reading it — default on** (`KEN_MCP_MMAP_MODEL`, ADR-045)

Every model-loading call site — the live index build, the pre-built-index load, and the M1 snapshot load — went through a full heap read of the 64 MB `model.safetensors`, and nothing shared that copy across the per-process repo cache (`KEN_MCP_CACHE_SIZE`): each cached repo paid for its own. `ken-mcp` now mmaps it by default instead.

- **Measured −18% peak RSS** (306,240 → 250,448 KB) building a hybrid index over ken's own repo.
- **The win compounds with `KEN_MCP_CACHE_SIZE`.** A read-only mmap's physical pages are shared by the kernel across every mapping of the same file — so N cached repos stop paying N separate copies of the model, a benefit a heap read can't get no matter how the cache is sized.
- **Embeddings are provably unchanged.** mmap only changes where the tensor bytes come from, never their values — verified bit-identical against the old heap-read path, so retrieval quality (NDCG/recall) needed no re-measurement.
- `KEN_MCP_MMAP_MODEL=0` is the escape hatch if a model directory sits on a filesystem where mmap misbehaves (e.g. some network mounts).
- **Unaffected:** the CLI (`ken index`/`search`/`build-index`) and `mcp.Run`'s embedded-corpus path — both short-lived or `//go:embed`-sourced, where mmap's ~17% slower cold start isn't a good trade (or isn't available at all).

Full writeup: [ADR-045](https://github.com/townsendmerino/ken/blob/main/docs/internal/DECISIONS.md#adr-045-ken-mcp-mmaps-the-embedding-model-cli-keeps-the-heap-read).

## Also in this release

Five routine dependency bumps via Dependabot: `go-sql-driver/mysql`, `modernc.org/sqlite`, `golang.org/x/time`, `golang.org/x/sync`, `gotreesitter` — all patch/minor version bumps, all green across macOS/Linux/Windows CI including the race detector and DB integration suites.

## Upgrade

No action required — default behavior is unchanged, and the memory reduction applies automatically. If you run `ken-mcp` with a large `KEN_MCP_CACHE_SIZE` across several repos, expect the biggest drop in resident memory.

```bash
brew upgrade --cask ken                                       # macOS/Linux (first time: brew install --cask townsendmerino/tap/ken)
scoop update ken                                              # Windows
go install github.com/townsendmerino/ken/cmd/ken@latest       # Go
go install github.com/townsendmerino/ken/cmd/ken-mcp@latest
```

Pre-built binaries for macOS / Linux / Windows (amd64 + arm64) are attached to the [release](https://github.com/townsendmerino/ken/releases/tag/v1.7.0). Full curated changelog: [CHANGELOG.md](https://github.com/townsendmerino/ken/blob/main/CHANGELOG.md).
