# ken v1.8.0 — markdown chunking activated + aikit correctness fixes

A retrieval-quality release. **The 1.0 public API is unchanged — upgrading is safe with no config changes**, though repos with `.md` files will see their chunk boundaries change (for the better) on re-index.

## Highlights

**`.md` files now chunk through the dedicated markdown chunker by default**

The markdown chunker (`aikit/chunk/markdown`) has been linked into `cmd/ken` and `cmd/ken-mcp` for a while, but nothing ever actually selected it for a file — every `.md` file silently fell through to whatever chunker was requested (`regex` by default, which has no markdown rules and falls back to the line chunker). `.md` files now get real heading-based chunk boundaries instead.

- `--chunker=line` remains an explicit opt-out if you want the old whole-file-fallback behavior.
- Retrieval quality re-measured on semble's 63-repo benchmark: hybrid recall@10 unchanged (0.973/0.969/0.995 all/nl/symbol), BM25-only recall ticks up +0.002 — this is a chunking-quality fix, not a ranking change.
- Newly covered by `TestChunkOneFile_MarkdownAutoRoute` (previously zero coverage on this path).

**Three real correctness fixes via an aikit bump (v1.31.0 → v1.45.1)**

14 releases, 152 commits — Dependabot's own PR only reached v1.42.0, so this went out as a manual bump instead:

- BM25's WAND unsound bound at B>1
- An ANN/HNSW scoring bug
- Duplicate-key handling in the inlined RRF fuse

No API changes. Verified with a full test pass against a real model (semantic/hybrid/recall paths actually exercised, not skipped) plus aikit's own embedding-cosine parity check.

**Reduced allocations on the hybrid rerank hot path**

`rerankTopK`, the query-boost step, and the per-file symbol-stem matching in the boosting helpers all shed avoidable allocations — a map replaced by a slice, an unnecessary defensive copy removed, per-file work memoized instead of repeated per chunk. Behavior-preserving, confirmed via byte-identical recall@10 on the semble corpus.

## Also in this release

Two routine dependency bumps: `github.com/modelcontextprotocol/go-sdk` 1.7.0 → 1.8.0, `github.com/jackc/pgx/v5` 5.10.0 → 5.11.0 — both green across macOS/Linux/Windows CI including the race detector and DB integration suites.

## Upgrade

No action required. If your corpus has `.md` files, expect (better) chunk boundaries to shift on the next re-index — this is quality-neutral-to-positive per the recall numbers above, not a regression to watch for.

```bash
brew upgrade --cask ken                                       # macOS/Linux (first time: brew install --cask townsendmerino/tap/ken)
scoop update ken                                              # Windows
go install github.com/townsendmerino/ken/cmd/ken@latest       # Go
go install github.com/townsendmerino/ken/cmd/ken-mcp@latest
```

Pre-built binaries for macOS / Linux / Windows (amd64 + arm64) are attached to the [release](https://github.com/townsendmerino/ken/releases/tag/v1.8.0). Full curated changelog: [CHANGELOG.md](https://github.com/townsendmerino/ken/blob/main/CHANGELOG.md).
