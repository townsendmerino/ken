# ken v1.6.0 — opt-in quantized dense retrievers + a real-code "apparent hang" fix

Feature release. The exact-cosine dense retriever gains two opt-in, **measured** quantized alternatives; a class of pathological-file stalls on ordinary C code is closed; and `ken doctor` learns to advise large repos. **The 1.0 public API and the default retrieval path are unchanged — upgrading is safe with no config changes.**

## Highlights

**Opt-in quantized dense retrievers — `KEN_ANN=flat-i8` / `flat-binary-i8`** (ADR-043)

ken's semantic arm has always been exact f32 cosine (`ann.Flat`). Two opt-in retrievers now trade a measured amount of accuracy for speed and memory — and we measured it three ways before recommending anything: a real 63-repo / 1,251-query benchmark, a 13k→800k synthetic scale ramp, and a real **584k-chunk Linux-kernel** spot-check.

- **`flat-binary-i8`** (binary prefilter + int8 rerank) — **zero measured end-to-end recall cost** at repo/mid scale, and ~**2× faster than exact `Flat` even at typical repo size**. The pick for most repos.
- **`flat-i8`** (int8) — the safer choice at **real kernel scale**, where `flat-binary-i8`'s agreement with exact cosine slips to **0.96** (vs `flat-i8`'s ~1.00) on large, clustered real embeddings — a gap only real data at scale revealed, not the benchmark or synthetic vectors.
- **`HNSW`** was evaluated and **declined** at every scale: competitive query past ~50k vectors, but multi-minute builds break `ken index --watch`'s 2 s republish contract, and it uses *more* memory than `Flat`, not less.

Default is unchanged (exact `Flat`) — this is a knob, not a behavior change. Method + numbers: [`dense-retriever-adoption-2026-09.md`](https://github.com/townsendmerino/ken/blob/main/docs/internal/dense-retriever-adoption-2026-09.md), [ADR-043](https://github.com/townsendmerino/ken/blob/main/docs/internal/DECISIONS.md).

**`ken doctor` now advises large repos.** A new "Tuning for your repo shape" guide in USERS.md maps size / churn / structure to the right flags, and on a repo whose snapshot holds ≥100k chunks `doctor` suggests `KEN_MCP_STAGED=1` (instant BM25 first query, background upgrade to hybrid).

## Fixed

**No more hang-looking stalls on ordinary C code** ([gotreesitter#1100](https://github.com/odvcencio/gotreesitter/issues/1100), ADR-044). A survey of a real 37,775-file `.c`/`.h` corpus found 504 files (1.33%) — clock drivers, GPU register tables, device-ID tables — tripping a `gotreesitter` C-grammar slowdown during structural enrichment (same failure class v1.5.1 fixed for C#, different grammar, many files). `ken index` / `search` / `bench` / `perf` now default a 2,000 ms per-file enrichment budget: a pathological file is skipped and logged, not hung on. (`ken build-index` stays exempt — its output is byte-identical by contract.)

**`ken-mcp` forced shutdown now exits non-zero.** Grace-period expiry and a second SIGINT/SIGTERM both previously exited `0`, indistinguishable from a clean drain even though an in-flight request was dropped. Grace expiry now exits `1`; a second signal exits `128+signal` (`130` SIGINT, `143` SIGTERM). **If you supervise `ken-mcp`, update any exit-code checks.**

## Security

`golang.org/x/crypto` 0.53.0 → 0.56.0 (pulling `x/net` 0.57, `x/text` 0.41), closing **GO-2026-6354 / GO-2026-6355**, reachable through go-git's SSH clone path; `govulncheck` is clean again. `aikit` 1.24 → 1.31 rode along (amd64-only quantized-matmul work, off ken's arm64 f32 path; validated no change to rerank scores or hybrid rankings).

## Upgrade

No action required — default retrieval and the public API are unchanged. Optionally: try `KEN_ANN=flat-binary-i8` for a faster/lighter semantic arm (or `flat-i8` on very large corpora); and if you supervise `ken-mcp`, note the new non-zero forced-shutdown exit codes.

```bash
brew upgrade --cask ken                                       # macOS/Linux (first time: brew install --cask townsendmerino/tap/ken)
scoop update ken                                              # Windows
go install github.com/townsendmerino/ken/cmd/ken@latest       # Go
go install github.com/townsendmerino/ken/cmd/ken-mcp@latest
```

Pre-built binaries for macOS / Linux / Windows (amd64 + arm64) are attached to the [release](https://github.com/townsendmerino/ken/releases/tag/v1.6.0). Full curated changelog: [CHANGELOG.md](https://github.com/townsendmerino/ken/blob/main/CHANGELOG.md).
